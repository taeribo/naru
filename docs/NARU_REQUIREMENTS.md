# NARU 서비스 요구사항

## 확정

- 나루는 3인 팀이 공개 출시를 목표로 개발하는 3D 웹 체험이다. 모바일 세로 화면을 우선하며 PC 브라우저를 지원한다.
- 일본 신사와 절을 모티브로 한 새해 문화 체험 광장이다. 중앙에 벚꽃나무와 돌길을 두고, 정원과 네 체험 구역을 잇는다. 시각 목표는 [겨울 하츠모데 레퍼런스](references/README.md)를 따른다. 기존 메인 화면 PNG는 초기 광장 디자인 기록으로 보존한다.
- 메인 화면에는 종울리기, 소원패, 운세뽑기, 휴식공간 버튼을 둔다. 중앙 상단에는 나루 로고, 우측 상단에는 작은 벚꽃 꽃잎 모양 후원 버튼을 둔다.
- 후원 팝업은 모바일 세로 대응, 닫기 버튼, 교체 가능한 QR 영역을 갖춘다. QR 이미지가 없는 동안 영역을 비워 둔다. 엽전 명칭과 아이콘은 사용하지 않는다. 후원은 자율이며 모든 체험과 이용 조건은 동일하다.
- 소원패 창에는 소원 작성과 다른 방문자의 공개 소원패 목록을 표시한다. 작성한 소원은 익명 식별자와 생성 시간을 부여해 기존 MySQL 저장소에 보관한다. 서버 입력 검증, 최신순 페이지네이션, WebSocket 갱신을 사용한다. 풍등 체험과 풍등 전용 상승·수면 연출은 제외한다. 겨울 신사 광장의 석등과 제등은 환경 조명으로 사용한다. 소원 신고와 관리자 숨김은 운영 기능으로 관리한다.
- 운세는 종합·연애·재물·직장·건강·가족·인간관계·성장운이다. 무료이며 카테고리별 결과는 서울 날짜 기준 하루 한 번 결정하고 횟수 제한 없이 다시 볼 수 있다. 각 카테고리에서 대길·길·흉 등의 등급과 문구가 함께 결정되도록 한다. 문구는 검수할 수 있도록 코드와 분리한다. 운세 카탈로그에는 기존 [운세 마이그레이션](../backend/db/migrations/V003__fortune_catalog.sql)을 사용하며 사용자별 결과 이력을 저장하지 않는다. 건강·재물 문구는 의학적 진단이나 투자 조언처럼 표현하지 않는다.
- 모든 공간이 동일 맵을 사용한다. 초기 운영 상한은 2개, 확장 상한은 10개, 각 공간 정원은 30명이다. 활성 공간이 26명에 도달하면 관리자 설정 범위 안에서 다음 공간을 자동 개설한다. 서버 자동 배정, 만석 시 대기열, 재연결 시 기존 공간 복귀 우선을 적용한다.
- 동일 공간에서 입장·퇴장과 위치를 WebSocket으로 동기화한다. 관리자 기능은 접속 현황, 최대 공간 수, 자동 개설과 입장 제어, 서버 상태, 권한 구분과 2단계 인증, 변경 감사 로그, 소원 신고·숨김을 포함한다.

## 권장

- 기존 React·TypeScript·Vite, Three.js·Fiber·Drei, Java·Spring Boot, MySQL·Docker Compose 구성을 사용하고 단일 서버 기준으로 검증한다.
- 화면과 저장 기능을 수직 단위로 개발한다. 초기 그래픽은 임시 에셋으로 명시하고 모바일 실기기 결과로 품질 기준을 보완한다.

## 미확정

- 후원 팝업의 제목·설명·하단 안내, 공식 QR 이미지, 결제·송금 제공업체 및 계약 조건. 확정 전에는 QR이나 결제·송금 연동을 추가하지 않는다.
- 소원 보관 기간, 운영 신고 처리 기준 및 관리자 권한 세분화.
- 기존 공개 소원 저장 구조의 향후 변경과 신고·숨김 운영에 필요한 데이터 모델.
- 실제 운영 배포 구성, 운영 비용, 최종 비주얼과 스마트폰 성능 기준.
