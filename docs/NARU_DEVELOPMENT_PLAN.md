# NARU 개발 계획

A는 3D·에셋, B는 클라이언트, C는 백엔드·DB·운영을 맡는 권장 분담이다. 실제 지정은 팀에서 확정한다. 설계 총괄자는 공통 API와 이벤트 형태를 먼저 조율한다. 아래 파일 경로는 수정 예상 범위다.

| 작업 및 목적 | 담당 | 예상 파일 | 선행 작업 | 완료 기준 | 테스트 |
| --- | --- | --- | --- | --- | --- |
| 1. MySQL 개발 경로 확인 (완료) | C | `compose.mysql.yaml`, `backend/src/main/resources/application-mysql.yml` | Docker 접근, 로컬 DB용 환경값 | Spring에서 개발 MySQL에 연결할 수 있고 기본 무DB 기동도 유지 | 별도 개발 환경의 JDBC `SELECT 1`, Compose Health, 기존 MockMvc |
| 2. 일본풍 광장과 체험 구역 | A | `frontend/src/scenes/`, `frontend/public/models/` | 일본 새해 문화 체험 구도 | 세로·가로에서 네 구역 진입과 이동을 확인하고 일본풍 광장의 에셋과 조명 최적화 | 브라우저 뷰포트와 스마트폰 터치·프레임 측정 |
| 3. 소원패 저장·페이지·이벤트 | C | `backend/src/main/java/kr/naru/`, DB 마이그레이션, `backend/src/test/` | 1, [초기 ERD v1.0](NARU_ARCHITECTURE.md#초기-erd-v10) 및 REST·이벤트 계약 검토, 마이그레이션 실행 승인 | MySQL 익명 저장, 최신순 페이지, 유효성 검증, 커밋 후 이벤트 및 신고·숨김 계약 | DB·REST·WebSocket 통합, 재기동 후 조회, 숨김 시 공개 제외 |
| 4. 공개 소원패 화면 | B | `frontend/src/features/WishPanel.tsx`, `frontend/src/services/` | 3의 인터페이스 합의 후 모의 데이터로 병렬 개발 | 최신순 페이지, 실시간 중복 방지, 오류·재연결 처리, 소원패 걸기 성공 안내 | 두 브라우저 등록·수신, 오프라인 재연결 및 페이지 경계 확인 |
| 5. 오미쿠지 등급 (구현) | B·C | `frontend/src/features/`, 별도 문구 데이터, 백엔드 운세 모듈 | 오미쿠지 등급과 기존 문구 유형 매핑 | 카테고리별 등급과 문구 표시, 당일 재열람 시 동일한 결과 | 8개 카테고리와 등급 분포, 서울 자정 경계, 반복 열람 |
| 6. 공간·이동·재접속 | C·B·A | 백엔드 공간·WebSocket 모듈, 프론트 통신 서비스와 캐릭터 장면 | WebSocket 계약, 공용 캐릭터 좌표 | 26명 개설, 30명 정원, 운영 상한, 대기열, 복귀와 이동 동기화 | 동시 접속 경계와 연결 해제·복귀 테스트 |
| 7. 관리자·운영·출시 검증 | C·B·A | 관리자 정책 문서, 관리자 API·UI, `.github/workflows/`, 운영 문서 | 권한 정책·2단계 인증 검토, 주요 기능 검증 | 운영 제어와 감사, 신고 처리, CI·부하·실기기 검증 완료 | 권한별 API, 변경 감사, 300명 목표 부하, PC·모바일 회귀 |

기존 소원 저장과 커서 기반 30건 페이지, WebSocket 목록 갱신을 공개 소원패에 연결했다. 풍등 상승과 전용 이벤트, 등불, 연못 반사 등의 연출을 제거했다. 운영 신고·숨김과 실제 스마트폰 검증은 남아 있다.

운세 8개 카테고리와 일일 결과, 네 체험 버튼, 공간 자동 배정·대기열·재접속·이동을 구현했다. 로컬 300명 WebSocket 부하 테스트에서 10개 공간과 301번째 대기를 확인했다. 오미쿠지 등급과 당일 재열람을 구현했다. 실제 기기와 운영 환경에서는 장시간 부하를 별도로 검증한다.

후원 UI는 초기 구현 범위에 포함했다. 실제 QR과 문구는 자율 후원 정책과 공식 수단 확인 뒤 적용한다.

## 진행 기준

설계 총괄자는 소원 저장 계약과 ERD를 먼저 리뷰한다. A의 장면 작업과 B의 목록 목업은 C의 DB 연결 확인과 병렬 진행할 수 있다. PR은 기능별로 작게 작성하고 공개 계약 변경 시 호출부와 테스트 영향을 기록한다. Git push·merge, 실제 마이그레이션 실행, 데이터 삭제, 운영 배포는 명시적 승인 후 진행한다.
