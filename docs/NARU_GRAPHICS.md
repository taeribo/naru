# 나루 광장 재질과 조명

이 문서는 이전 그래픽 작업과 당시 측정값의 기록이다. 현재 디자인 목표는 [겨울 하츠모데 레퍼런스](references/README.md)와 [공통 지침](../AGENTS.md)을 따른다.

## 적용 범위

React Three Fiber와 Three.js로 생성한 기존 광장 메시와 UV를 사용한다. 건물과 나무의 모델, 체험 구역 좌표, 이동 계약과 카메라를 유지한다. 광장 전체에 현지 크기에 맞춰 반복하는 석재 UV를 적용한다. 기존 길과 체험 구역은 별도 재질 톤으로 구분하며 광장 밖 자갈과 창살 패턴은 절차적 텍스처를 유지한다.

| 대상 | 재질 | 원본 |
| --- | --- | --- |
| 광장 돌길과 계단 | 회색 돌과 줄눈이 있는 색상, 표면 노멀, 거칠기 | [Cobblestone Floor 02](https://polyhaven.com/a/cobblestone_floor_02) |
| 기둥과 목재 구조 | 목재 색상과 결, 표면 노멀, 거칠기 | [Wood Table 001](https://polyhaven.com/a/wood_table_001) |
| 벚꽃나무 줄기와 가지 | 나무껍질 색상과 갈라진 결, 표면 노멀, 거칠기 | [Bark Brown 01](https://polyhaven.com/a/bark_brown_01) |
| 정자와 원경 건축의 기와 | 낮은 채도의 기와, 표면 노멀, 거칠기 | [Grey Roof Tiles 02](https://polyhaven.com/a/grey_roof_tiles_02) |

소스 이미지 12장을 512×512 JPEG로 가공해 `frontend/public/textures/courtyard/`에 저장한다. 전체 용량은 937,683바이트다. 색상 맵은 sRGB, 노멀과 거칠기 맵은 데이터 색 공간을 사용한다. 노멀은 Three.js에 맞는 OpenGL 방향이다. [Poly Haven CC0 사용 조건](https://polyhaven.com/license)

## 렌더링

- 저녁노을에 맞춰 따뜻한 방향광과 은은한 보라 계열 반구광을 사용한다. 주변 점광원과 기존 창 발광은 따뜻함을 더한다.
- 벚꽃은 연분홍과 아이보리를 섞고 재질이 주변 빛에 반응하도록 한다. 수관 인스턴스는 최대 9,000개, 좁은 화면은 4,400개, 먼 시점에서는 2,600개를 그린다.
- 나무와 체험 시설은 부드러운 접지 그림자를 공유한다. 화면 폭이 680px 미만이면 렌더 해상도 배율을 최대 1로 제한한다.
- 기존 소원패의 작성·조회 흐름을 유지한다. 연못은 중앙 벚꽃나무 뒤에 두고, 수면 셰이더에서 시점에 따른 하늘 반사와 잔물결을 표현한다. 광장 석재는 건조한 무광으로 유지한다. 연못용 추가 장면 렌더 패스는 사용하지 않는다.

일본식 정자·도리이·성의 형상은 그대로 사용한다. 디테일을 높일 필요가 있을 때는 정자 처마와 종각 등 가까이서 보는 모델을 우선 검수한다. 현재는 GLB를 추가하지 않는다.

## 첫 재질 적용 전후 측정

| Chrome 뷰포트 | 프레임률 전 → 후 | 프레임 간격 p95 전 → 후 | 브라우저 load 이벤트 전 → 후 |
| --- | --- | --- | --- |
| 1200×800 | 2.1 → 2.7 FPS | 667 → 483 ms | 510 → 492 ms |
| 390×844 | 2.9 → 4.6 FPS | 483 → 267 ms | 494 → 357 ms |

같은 로컬 Vite 개발 서버에서 헤드리스 Chrome의 SwiftShader로 정면 약 4초를 단일 측정했다. 브라우저 load 이벤트에는 3D 재질 로딩 완료가 포함되지 않으므로 실제 광장 진입 시간은 별도 측정이 필요하다. 실제 GPU와 스마트폰에서의 30 FPS 목표는 미검증이다. 300명 서버 WebSocket 부하 결과와는 별개의 지표다.

### 전체 포장·노을·연못 적용 후

| Chrome 뷰포트 | FPS | WebGL 드로우 호출/프레임 | 브라우저 load 이벤트 |
| --- | ---: | ---: | ---: |
| 1200×800 | 2.7 | 272 | 508 ms |
| 390×844 | 4.5 | 176 | 545 ms |

동일한 SwiftShader 환경에서 정면을 약 4초간 측정했다. 첫 재질 적용 전에는 드로우 호출을 계측하지 않았다. 실제 스마트폰 GPU, 3D 진입 완료 시간과 30 FPS 목표는 별도 검증이 필요하다.

## 촬영 파노라마와 대기 원근

하늘은 1024×512 Radiance HDR 파노라마를 로컬에서 읽고, 구면 방향 벡터에 따라 샘플링한다. 밤 느낌을 위해 실제 촬영한 명암에 남색 상공과 분홍빛 지평선 색을 혼합한다. 같은 HDRI를 환경 조명에 사용하며 화면 하늘 밝기와 환경광 강도를 따로 둔다. 최종 파일은 1,309,268바이트이며 기존 PBR JPEG 12장과 합쳐 2,246,951바이트다. [Poly Haven Evening Road 01 (Pure Sky)](https://polyhaven.com/a/evening_road_01_puresky) · [CC0 라이선스](https://polyhaven.com/license)

- 후지산 위치와 배율을 유지하며 산 표면과 설선의 색 편차를 조정했다. 여러 거리의 언덕 윤곽을 다듬고 멀수록 하늘과 비슷한 저채도 색을 섞는다.
- 마을 뒤의 색 있는 빌보드 구름을 촬영 파노라마와 장면 안개로 대체했다.
- 석재 PBR의 UV와 타일 크기는 유지하고, 위치에 따른 저주파 색 편차를 사용해 같은 텍스처가 이어지는 느낌을 줄였다.
- 도리이 발밑에 부드러운 접지 음영을 추가했다. 실시간 그림자 지도나 후처리 패스는 사용하지 않는다.
- 수면색은 새 하늘에 맞췄다. 광장 포장에는 수면 효과를 사용하지 않는다.

## 광장 배치 개정

중앙 참배축을 먼저 읽을 수 있도록 입구에서 도리이와 가운데 벚꽃나무를 지나 후방 본전으로 이어지는 돌길을 두었다. 진입 방향을 기준으로 왼쪽의 운세·소원패와 오른쪽의 종각·휴식 공간은 앞뒤 거리를 두었다. 네 구역은 같은 판석 바닥 위에서 전용 지선으로 이어진다. 입구 가까이는 낮은 화단과 석등을 함께 두어 걸어 들어오는 방향을 표시한다.

| 구성 | 좌표 |
| --- | --- |
| 시작 카메라 / 기준점 | (0, 24, 54) / (0, 3.35, -2), 수직 시야각 60° |
| 도리이 | (0, 1.2, 22.3) |
| 벚꽃나무 | (0, 0, 0) |
| 본전 / 계단 | 본전 (0, 0, -47), 계단은 본전 앞쪽 |
| 운세뽑기 / 소원패 | (x, z) = (-24, 5) / (-31, -17) |
| 종울리기 / 휴식공간 | (x, z) = (24, 6) / (35, -16) |

배치 변경의 주요 파일은 `PlazaScene.tsx`, `terrain.ts`, `StoneCourtyard.tsx`, `CourtyardLandmarks.tsx`, `Japan.tsx`다. 후지산과 네 작업 구역은 유지한다. 연못은 벚꽃나무 뒤 (0, 0, -13)로 이동하고, 북쪽 본전과 원경 건물은 사각 테두리 너머에 둔다. 연못은 서버가 검사하는 이동 장애물이다. 시작 화면과 모바일 세로 화면은 같은 중앙축을 보며, 모바일에서는 화면 회전이나 상단 메뉴로 좌우 체험에 접근할 수 있다.

최종 레이아웃의 동일한 소프트웨어 Chrome 측정은 PC 1.9 FPS·299 드로우 호출/프레임, 모바일 크기 3.4 FPS·169 호출/프레임이었다. 추가 본전이 일부 프레임 비용을 늘렸고, 반복되는 화단·석등의 기하 데이터를 재질별로 병합했다. 실제 GPU와 스마트폰에서는 별도 측정이 필요하다.

## 공간 재구성

```text
                  북쪽 산·숲·원경 마을
           성       본전·계단        마을       (이동 경계 밖)
                        │
                   연못과 양쪽 우회로
    소원패 ────────┐    │    ┌──────── 휴식 정자
                   └─ 벚꽃 마당 ─┘
    운세 목조채 ───────┤    ├───────── 종각
                        │
                  도리이·입장 계단
             낮은 정원  참배길  낮은 정원
                     시작 카메라
```

입장 카메라는 (0, 4.1, 44.5), 기준점 (0, 2.5, -4), FOV 72°다. 기존 회전, 확대·축소와 서버 이동 범위를 사용한다. 바닥의 모서리 석재를 반투명하게 처리해 그 아래 이어지는 흙·이끼 지형에 섞고, 이동 범위 밖에서부터 완만하게 지형이 올라간다. 네 체험 구역은 기존 동선을 사용하고 기단과 목조 건축물의 규모를 키웠다. 구역 안내 버튼은 가까이 접근하거나 마우스를 올렸을 때만 나타나며 상단 메뉴와 건물 클릭은 계속 사용할 수 있다.

연못은 (0, 0, -13)을 중심으로 38×12이며, 본전은 북쪽 이동 경계 바깥 (0, 0, -47)에 있다. 연못을 가로지르는 이동은 서버가 막고 양옆 돌길로 돌아갈 수 있다. 후지산과 성은 기존 큰 배치를 유지한다. 진입로, 각 건물과 바깥 숲의 소나무류·관목·바위는 구역 단위로 묶고 다섯 종류의 인스턴스 배치로 반복한다.

외부 GLB 후보도 검토했다. 이번에는 기존 구조와 모바일 목표에 맞는 신사·수목 모델을 확보하지 못해 절차적 모델을 사용한다. 추가 검수 우선순위는 신사 본전과 도리이의 목조 디테일, 벚꽃나무의 덩어리 표현, 대·중·소 소나무와 자연석이다. 촬영 파노라마와 로컬 PBR 맵을 신규 외부 모델의 재질 기준으로 사용한다. [검토한 소스 예시](https://zenodo.org/records/10385703) · [Poly Haven 자연석 모델](https://polyhaven.com/a/rock_moss_set_01)

낮은 입장 시점 적용 전후의 로컬 SwiftShader 결과는 다음과 같다. 두 화면은 각각의 기본 입장 카메라로 캡처했다.

| Chrome 뷰포트 | 전 → 후 FPS | 전 → 후 드로우 호출/프레임 |
| --- | ---: | ---: |
| PC 1200×800 | 2.0 → 2.4 | 304 → 311 |
| 모바일 390×844 | 3.8 → 4.3 | 174 → 175 |

모바일 크기의 Chrome 에뮬레이션은 실제 모바일 GPU의 확인을 대체하지 않는다. PBR 맵과 HDRI는 합계 약 2.25 MB이며 GLB를 새로 추가하지 않았다.
